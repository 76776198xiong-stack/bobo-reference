**用途**：啵啵的大决策都在这一页，带理由和出处。大决策定完，以后作者只做小决策。想不起“为什么这么定”时，先查这里。

### 手的规则（B5a，作者 11-02 定，取代 B5 里手的样子）

- **出手从腮帮子来**（作者 11-04 定，取代原来的“从身体两侧拉出短手臂”）：腮帮子先鼓起两个小包，“啵”一声弹出来，变成两只团子手；要更多手，就再鼓、再“啵”。收手时，手飞回腮帮子，“啵”一声缩回去，表面泛一圈涟漪。
- 手可以贴在身边干活，也可以飞出去干别的事。
- 指向时，团子顶端鼓出一个小尖；拿东西时，东西像被果冻粘住一样贴在团子上。
- 手多不设限。啵啵是 AI 原生的，因为懒做出反常识的举动，正合人设。
- 不纠结完美。抽象一点的道具也可以，比如不太像纸的任务单，可爱就行。
- **动作参考**：作者提到经典动画《果宝特攻》，角色也是团子形状、小圆球手。可以参考里面的动作和表演思路，不借用它的角色设计。

**以后提示词里写手，统一用这句**：

> 手是圆圆的果冻团子手，从腮帮子来：腮帮子先鼓起两个小包，“啵”一声弹出来，变成两只团子手；要更多手，就再鼓一次、再“啵”一次。手可以贴在身边干活，也可以飞出去拿东西；收手时飞回腮帮子，“啵”一声缩回去。指向时团子顶端鼓出一个小尖；拿东西时，东西像被果冻粘住一样贴在团子上。

### 选题方向（顾问建议，待作者确认）

**选什么样的词**（已由 E7 确认）：

- 公共知识里的概念：有出处，换谁讲都成立。
- 不是常识。
- 根据词，用故事讲出来，形式自由。不强求“偷懒场景”。

**从哪些领域选**（按作者的兴趣和储备）：

| 领域 | 例子 | 主要出口 |
|---|---|---|
| 博弈与决策 | 古德哈特定律、谢林点、承诺机制 | 纯流量 / 成长 |
| 心理与认知 | 高敏感、习得性无助 | 成长（可和开挂的熊配对） |
| 社会与经济概念 | 林迪效应、劣币驱逐良币 | 纯流量 |
| 哲学与思维模型 | 奥卡姆剃刀、忒修斯之船 | 纯流量 |
| AI 概念（讲词，不讲工具） | 如“AI 幻觉” | AI（通向以后的杨傲雄） |

**永远不碰**（E6）：

- 财经专业内容：抖音 2025-12 起禁止未经财经认证的账号发布。
- 医疗、营养建议：平台审核严格。
- 玄学。

**选题怎么来**：

- 作者想学的东西：agent 先研究，先讲给作者听，作者是第一个观众。
- 流量调研：同类爆款、Grokbot 的《泛知识调研》和 YouTube 灵感候选。
- 发布后的评论。

**选题顺序**：观众想看什么 → AI 研究得透、熊看懂了 → 熊想学、想解决。改自作者 10-23 定的“观众想看什么 → 我有把握 → 我想解决”。

### 选题卡（小决策的单位）

agent 每出一个选题，就填一张卡；作者只回答“做 / 不做 / 改”。

```
词：
一句话解释（20 字内）：
故事（用什么故事把这个词讲出来）：
熊派活（开场一句）：
流量依据（同类视频数据或搜索热度）：
出口：纯流量 / 成长（配对熊的哪条） / AI
来源（至少 2 个可靠出处）：
风险：是不是常识；是否涉及财经、医疗、玄学
作者决定：做 / 不做 / 改
```

## 六、生产循环（作者已定）

**作者做三处决定，每一处决定都触发 AI 的下一步**：

选题卡 → **作者定选题** → AI 写脚本 → **作者定脚本** → AI 做片 → **作者审成片** → 发布 → 数据回看

**讲法（作者定，具体版本做的时候多测）**：

- 啵啵自述：有心理活动，也有台词。
- 熊不出镜。“熊派活”由啵啵自己说出来，比如“熊又给我派活了”。
- 不定死骨架。每条只守几样：一条一个词为核心；用故事讲；知识准确、有出处；和开挂的熊配对的那条，结尾把判断交回熊。

## 六之一、生产流程：借鉴 Grok Bot 工作流（作者已定）

**参考的工作流**（Grokbot 整理，作者转来；完整版在 Grokbot 那边 `/workspace/douyin/keith-grokbot/工作流梳理.md`，待放进 GitHub）：

- 多个 Bot 分工，老板只跟监制说话：
  - 监制：分任务、做检查；
  - 编导：照口播稿逐句出画面方案；
  - 配音师：豆包语音，一条几毛钱，同时出逐字时间表；
  - 动效师：用 Remotion 写代码，做动画、字幕和音效。
- 流程：
  1. 口播稿定稿；
  2. 编导出画面方案；
  3. 监制拆场景，一个场景只讲一件事；
  4. 每个场景先配音，再按逐字时间表卡动画、字幕和音效，检查、确认后才做下一个；
  5. 全部确认后合成，加背景音乐。
- 最关键的是**先有声音，动画才知道什么时候动**；画风靠给参考样片来定。

**用到啵啵上**：

| 角色 | 谁 | 做什么 |
|---|---|---|
| 总控兼编导 | Claude | 选题卡；口播稿（啵啵自述）；逐句画面方案，即表演表：台词、表情旋钮、身体动作、手、画面和镜头、音效 |
| 监制 | F1 测试胜出那一边（Codex 或 Grok Bot） | 拆场景，检查每个场景；作者在制作阶段只跟它说话 |
| 配音师 | 同上，用 F2 选定的工具 | 配音，出逐字时间表 |
| 动效师 | 同上 | 按时间表卡口型、眼睛、手和身体动作，加字幕和音效 |
| 美术 | ChatGPT B | 需要新姿态、新道具时出图 |

**流程**（保持作者的三处决定）：

1. 选题卡 → **作者定选题**
2. 口播稿 → **作者定脚本**
3. 编导出逐句画面方案
4. 监制拆场景
5. 每个场景：配音 → 逐字时间表 → 动画 → 监制检查
6. 合成，加背景音乐和“啵”的标志音
7. **作者审成片** → 发布

**场景确认**：试运行期（前 3 条）作者逐个场景确认；之后由监制检查，作者只审成片。这样既学到“一段一段确认、坏了只返工那一段”，又不给作者加决策点。

**“啵”的标志音**：用代码生成，手从腮帮子弹出来、收回去、断开飞出去的时候用，做成啵啵的声音标志。
